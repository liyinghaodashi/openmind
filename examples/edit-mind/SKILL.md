# 编辑 .mind.md 思维导图

把文件理解为一棵或多棵有序的节点树。Markdown 标记用来表达节点之间的父子关系；不要按文章的章节、正文和排版习惯组织它。使用本 skill 无需了解任何软件代码或渲染实现。

## 结构规则

| 节点深度 | 写法 | 父节点 |
| --- | --- | --- |
| 1 | `# 主节点` | 无；同一文件可有多个主节点 |
| 2 | `## 分支` | 最近的所属 `#` |
| 3 | `### 主题` | 最近的所属 `##` |
| 4 | `- 细分节点`，行首不缩进 | 最近的所属 `###` |
| 5 及更深 | 缩进的 `- 子节点` | 所属的上一层列表节点 |

- 路径严格遵循 `# → ## → ### → 嵌套 -`，不能跳过中间层级。任意节点都可以是叶子，不必为了凑齐层级添加子节点。
- 标题顶格写，最多使用三级标题；第四层开始使用 `-`，不用 `####` 或更深标题。
- 每个节点独占一行，结构标记后加一个空格。节点的说明、示例和细节需要出现在导图中时，也写成合适的子节点。
- 新建列表每深入一级增加两个空格，不用 Tab；同级缩进一致，退回祖先层级时与该层对齐。编辑已有文件时保留其一致且有效的空格缩进，不为统一格式重排无关分支。
- 同级节点按文件中的先后顺序排列。遇到同级或更高层级的节点，前一个分支结束；空行只用于阅读，不结束父子关系，也不创建节点。
- `#`、`##` 下不能直接接列表节点；`###` 下的第一层列表必须从行首开始，不能直接写缩进列表。
- 只有行首的结构标记决定层级。例如 `- # 标题文字` 仍是列表节点，`# 标题文字` 是它的内容。

```markdown
# 产品规划

## 用户体验

### 文件操作
- 打开文件
  - 最近使用
  - 从文件夹选择
- 保存文件
  - 自动保存
    - 保存失败时提示

### 快捷键
- 1. 选择节点
- 2. 修改内容

## 后续想法

# 学习计划

## 阅读

### 数据库
- 索引
```

这里“打开文件”和“保存文件”是兄弟节点；“最近使用”属于“打开文件”；“保存失败时提示”属于“自动保存”。“后续想法”是没有子节点的二级节点。“学习计划”开启另一棵独立的树。

## 内容与元数据

- 节点名称应表达一个清晰的概念、行动或结论。细分时让子节点解释或展开父节点，让兄弟节点表达并列内容；保留用户的事实、限定条件和原有顺序，避免为了短小丢失含义。
- 不把节点展开成长篇正文，也不把普通段落、表格、引用、代码围栏、HTML 注释或 YAML frontmatter 当作导图节点。不要用这些块包裹需要出现在导图中的内容。
- 不使用 `*`、`+` 或有序列表标记表达节点。需要步骤编号时写成 `- 1. 第一步`、`- 2. 第二步`，编号只是节点文字。
- 节点末尾可以带颜色元数据，例如 `## 用户体验 [color:#5EAA80]`。颜色接受 `#RGB` 或 `#RRGGBB`；新写时优先使用六位 HEX，整行只写一个颜色后缀。重命名或移动节点时保留原有颜色，不将其当作节点名称，也不擅自给后代补颜色。
- 已有文件中的非节点内容、注释及未知标记应原样保留；不要因为它们不属于节点语法就删除或改写。若它们与待移动分支混排，使归属不明确，先确认归属再移动，避免后续缩进节点失去父节点。

## 修改方法

1. 先读目标分支及必要的祖先、前后兄弟，确定节点的完整路径，例如“产品规划 / 用户体验 / 文件操作 / 保存文件”。同名节点不能仅凭文本全局替换；无法从请求确定目标或新归属时，先澄清。
2. 按用户要求做局部修改。新增节点放在目标父节点的分支范围内，使用下一层的标记；新增兄弟使用相同标记和缩进。不要擅自重命名、排序、合并其他分支。
3. 移动节点时默认携带全部后代，保持子树内部关系与顺序。跨层级移动要按新深度重新编码整棵子树，必要时在标题和列表之间转换，不能只改节点自身的标记。
4. 删除分支包含其后代；若用户要求“只去掉这一层、保留内容”，将后代提升并重新编码。用户对删除范围表达不清时，先确认，不静默丢弃后代。
5. 如果现有目标结构已经跳级或缺少父节点，先确定内容归属。不要猜测并补出没有语义的占位父节点，也不要顺手修复整份文档。

例如，将上面的“保存文件”分支移到“用户体验”下，作为“文件操作”的兄弟，应从原位置移除整棵子树，并在该 `## 用户体验` 范围内写为：

```markdown
### 保存文件
- 自动保存
  - 保存失败时提示
```

“保存文件”由第四层变成第三层，因此它的所有后代也一起提升；不能保留原来的列表缩进。

## 完成前核对

- 按节点树重读改动区域：每个节点的父节点、兄弟顺序和用户要求一致，没有跳级、孤立列表或四级标题。
- 新增内容均处在正确的分支范围内；跨层级移动已转换所有后代，原位置没有残留副本。
- 没有因插入标题或改变缩进，使原有的后续节点意外换了父节点；删除没有遗留孤立后代。
- 节点文字、颜色后缀、无关内容和原有注释按修改范围保留；文件名仍以 `.mind.md` 结尾。
- 如果向用户交付完整文件，文件中只写实际内容，不将整份内容套在 Markdown 代码围栏里。简短说明修改了哪些分支，不宣称完成未经执行的软件显示验证。
